5. Why Each Is Useful — Decision Sciences Lens

◆ feature/graphiti — When to use

  • Evolving documents over time — if you simulate public reaction to a company across 6 months of press releases, graphiti tracks "Apple CEO changed from X to Y on date Z" automatically. Main can't do this.
  • Multi-document corpora — graphiti deduplicates "Tim Cook" across 50 chunks automatically. Main creates 50 separate nodes.
  • Provenance tracing — every fact links back to the episode (chunk) that produced it. You know where each fact came from.
  • Community detection — graphiti auto-clusters related entities into communities. Useful for finding "who is connected to whom" in a corporate scandal simulation.
  • When to merge to main: After writing an adapter that maps graphiti's Neo4j schema to EntityReader and the simulation search queries (~2 days work).

▲ feature/pydantic-ner — When to use

  • Immediately — merge today. Zero integration work. The only file changed is ner_extractor.py and it has a fallback path.
  • Better attribute population — the typed schema forces the LLM to fill industry, title, revenue etc. on every entity. Main leaves these empty. Richer attributes = richer agent personas in simulation.
  • Eliminates JSON retry failures — in production, ~5–15% of NER calls fail JSON parsing and retry. Pydantic + json_schema drops this to near 0%. Faster graph builds.
  • More complete relation extraction — the typed edge schema tells the LLM exactly what relation types exist and what source→target pairs are valid. It finds more relations per chunk.
  • When to merge to main: Now. It's ready. The original path is the fallback.
Recommended order Step 1 (this week): Merge feature/pydantic-ner → main. Immediate quality improvement, zero risk, no new dependencies.
Step 2 (next sprint): Write the EntityReader adapter for graphiti's schema. Then merge feature/graphiti → main as the full pipeline replacement. The Pydantic model factory code in pydantic-ner is shared with graphiti-service — so the two branches build on each other.
